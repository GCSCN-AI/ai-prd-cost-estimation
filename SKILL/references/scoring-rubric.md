# 评估计量与验证细则

本文件是 `ai-software-estimation` Skill 的可重放规则表。若组织批准了不同的权重、阶段区间或阈值，应保存规则版本、批准人和生效日期，并在报告中说明。

## 1. 门禁

门禁函数为 `G(p) ∈ {pass, not applicable}`。项目必须逐项给出引用或明确的评审假设：

| 条件 | 通过证据 | 失败处理 |
| --- | --- | --- |
| `G1` 业务目的 | 组织经营、管理、运营、合规或对外业务流程；或消费者参与的交易、预约、服务交付、订单履约、活动运营 | `not applicable` |
| `G2` 对象与动作 | 有业务对象和创建、提交、审批、确认、取消、履约、查询或变更动作 | `not applicable` |
| `G3` 参与者与责任 | 至少两个可识别参与者，或消费者与商家/运营/服务提供方；责任关系可定位 | `not applicable` |
| `G4` 系统边界 | 系统、外部服务、排除项和责任主体可区分；混合产品可隔离可独立交付的业务子系统 | 无法隔离时 `not applicable` |
| `G5` 领域适配 | 主要工作量由业务规则、工作流、交易、状态、记录、库存、容量、排班、权限或运营约束驱动 | 触发纯内容/社交、游戏、工具、创意、实时控制、科学计算、基础设施或平台软件排除 |

B2C 项目只有在消费者与商家、运营方或服务提供方之间存在可观察的业务流程时才适用。门禁失败后不计算 `US`、`C`、`CF`、`D`、`V`、`AS` 或 `P`。

## 2. 证据账本

每个功能过程或复杂度判断使用一行：

```text
id | source | citation | actor | trigger | outcome | main_path | alternate_path |
data_interaction | acceptance | method_unit | proposed_weight | evidence_level |
evidence_state | confidence | reviewer_decision | reviewer_note
```

证据状态：

- `Observed`：原文直接支持，可定位到文件版本和位置。
- `Assumed`：为计算采用的明确本地约定。
- `Unknown`：资料未提供的必要信息，必须进入风险或澄清清单。
- `Rejected`：被边界排除的解释，如页面数量、测试条数或实现库数量。

证据等级：

| 等级 | 最低证据 | 计量处理 |
| --- | --- | --- |
| `E0` | 只有能力或页面描述，没有参与者、触发条件和业务结果 | 不进入 `US` |
| `E1` | 有参与者、触发条件和业务目标/结果 | 可进入 provisional UUCP；缺少输入/输出或读写细节的部分标 `Assumed` |
| `E2` | `E1` 加上输入/输出、数据交互和验收条件 | 可按观察证据进入 UUCP |

需求条目、功能过程、设计/数据/接口证据和验收场景必须形成追踪矩阵。没有对应功能过程的条目不得通过补写文字计入。

## 3. 主计量方法

每个项目只选一个主单位：

| 证据形态 | 主方法 | 约束 |
| --- | --- | --- |
| Actor、用户目标、用例和事务叙述，缺少字段细节 | UCP/UUCP | 按用户目标分组，不把控件当用例 |
| ILF、EIF、EI、EO、EQ 可逐项识别 | NESMA/IFPUG | 统一使用一种计数法和成熟度规则 |
| Entry、Exit、Read、Write 可逐项识别 | COSMIC | 只计软件边界内的数据移动 |
| 只有能力清单 | provisional UUCP | 档位为假设，置信度低 |

页面、实体、API、文件、定时任务、组件、插件和测试步骤是分解或验证维度，不与主单位相加。

### provisional UUCP 规则

```text
UUCW = 5S + 10A + 15C
US   = UAW + UUCW
```

其中 `S/A/C` 是简单、平均、复杂功能过程数；只有 `E1/E2` 进入计数。Actor 规则为：人类 Web 角色 `3`，文本或协议型外部参与者 `2`，自动化或简单外部服务 `1`；纯浏览者不计。若组织批准了不同规则，必须以版本化规则替换，不得由模型临时改写。

## 4. 复杂度锚点

七个维度均为 0～5 分。先引用证据并列出未知项，再给分：

| 维度 | 0～1 | 2～3 | 4～5 |
| --- | --- | --- | --- |
| `L` 业务逻辑 | 直接 CRUD 或简单校验 | 条件组合、计算、多种结果 | 规则链、例外密集、难以回退 |
| `W` 流程与状态 | 无状态或单步 | 一个简单状态流 | 严格、不可逆、定时或事件驱动转换 |
| `D` 数据一致性 | 单对象保存 | 两个对象联动 | 跨对象事务、唯一性、幂等、并发控制 |
| `A` 权限与安全 | 一个认证角色 | 角色级访问 | 对象/字段级权限、访客令牌、租户和敏感数据隔离 |
| `I` 外部集成 | 无外部依赖 | 一个稳定接口 | 多系统、重试、限流、签名、异步补偿 |
| `Q` 可靠性与性能 | 普通 Web 要求 | 有容量或响应目标 | 高可用、峰值、离线、实时或严格 SLO |
| `O` 交付与运维 | 单环境 | 测试和基础监控 | 多环境、迁移、灰度、备份恢复和持续运维 |

通用交易型系统的默认权重为：

```text
L/W/D/A/I/Q/O = 0.25/0.20/0.15/0.15/0.10/0.10/0.05
C = 0.25L + 0.20W + 0.15D + 0.15A + 0.10I + 0.10Q + 0.05O
```

最低证据包：`L` 规则表或计算公式；`W` 状态机或转移条件；`D` 数据模型、事务、唯一性、幂等或并发要求；`A` 角色—资源—操作矩阵、租户或敏感字段说明；`I` 接口契约及重试/补偿规则；`Q` 容量、响应、可用性、峰值、离线或 SLO 要求；`O` 环境、部署、迁移、备份、监控、发布或恢复要求。

只有评审人确认某维度在系统边界内确实不存在，且没有待确认外部依赖时，才可将“不适用”按 0 计入；否则保留 `Unknown`，不发布完整点值。

## 5. `CF`、`D`、`V` 和成本

```text
AS = US × CF
P  = AS × (C / C') × D × V
```

`CF = f(M,R)`：`M` 选择基础区间，`R` 决定区间内取值。起始阶段区间如下：

| 阶段 | 定义 | `CF` |
| --- | --- | ---: |
| `M0` | 概念说明，目标和范围仍在讨论 | 1.50～2.00 |
| `M1` | PRD 草稿，边界或验收不完整 | 1.50～2.00 |
| `M2` | 结构化 PRD，有功能过程记录，尚无设计评审 | 1.26～1.50 |
| `M3` | 设计评审通过，状态、接口、部署和非功能要求确认 | 1.00～1.25 |
| `M4` | 迭代基线，需求稳定且有迭代速度数据 | 1.00 |

风险登记表 `R` 覆盖六类风险：范围和边界、验收条件、外部接口和供应方、数据模型/权限/组织隔离、性能/可用性/合规、版本/迁移/部署。缺少一类或存在无责任人/关闭条件的高影响风险时，不取区间下界。

`D` 需要技术栈、团队能力、平台复用、质量门禁、部署范围和平台边界证据；`V` 需要统一规模口径的历史实际人日/成本和时间切分留出验证。`V` 必须是与成本公式量纲一致的复杂度归一化单位工作量或单位成本因子；若原始资料是生产率倒数，先按批准规则换算。没有 `D` 或 `V`，`P` 为不可评估。

## 6. 置信度与验证门槛

按参数记录：

| 指标 | 检查方式 |
| --- | --- |
| 证据覆盖率 | 有引用或明确假设的计数项/总计数项；临时评估门槛为 100% |
| 假设率 | `Assumed` 项/计数项；越高置信度越低，除非约定已批准且稳定 |
| 未知率 | 未知必要字段/必要字段；未知不得转为零 |
| 边界稳定性 | 两位评审人的 `US` 相对差异、`C` 逐维差异 |
| 重现性 | 固定模型、提示词和规则下账本重跑相似度，公式精确重放 |
| 验证强度 | `D` 原型、`CF` 风险/变更回放、`V` 时间留出回测 |

使用最弱环节原则：

```text
Conf_US = min(证据覆盖、边界稳定、评审一致、重跑稳定、参数验证)
Conf_C  = min(维度证据、锚点校准、评审一致、重复计费检查、重跑稳定)
Conf_CF = min(阶段确认、风险登记完整度、负责人批准、历史回放、C/CF 分离)
Conf_AS = min(Conf_US, Conf_CF)
Conf_P  = min(Conf_US, Conf_C, Conf_D, Conf_CF, Conf_V)
```

“高/中/低”是序数标签，不是概率。达到“中高（受限）”的启动条件：

- `US` 和 `C` 的计数/评分项 100% 有引用、明确假设或批准的不适用判断。
- `US` 的 `E1/E2` 追踪覆盖 100%，功能过程 F1 ≥ 0.85，重复率 ≤ 5%，引用正确率 ≥ 95%。
- `C` 七维均有最低证据包或批准的不适用判断，重复计费为 0，逐维 MAE ≤ 0.5。
- 两位评审人的 `US` 相对差异 ≤ 10%，`C` 逐维绝对差异 ≤ 0.5。
- 固定配置重跑时 `US` 变化 ≤ 5%，`C` 变化 ≤ 0.25。

缺少完整历史回测时，`US/C` 最多标为“中高（受限）”。`CF` 达到“中”还需负责人确认 `M`、六类风险全检查、高影响风险有责任人和关闭条件、规则表可重放，以及至少一轮按时间顺序的变更回放；区间覆盖率启动门槛可取 80%，须由组织校准。

## 7. 最低验证门禁

- 所有计数项均有引用或显式假设。
- 主计量方法已声明，未混加异构单位。
- `US`、`AS` 和适用的 `P` 可从账本确定性重算。
- 第二评审人能够区分 `Observed`、`Assumed`、`Unknown` 和 `Rejected`。
- 同一证据只在 `C` 或 `CF` 中计一次。
- `V` 使用时间留出回测，或明确标为外部/临时基线。
- 记录规则、模型、提示词、索引、人工修改、审批人和时间戳。
